# API101 compatibility

This branch adapts MIUIQOL 1.1.17 to the modern libxposed API101 lifecycle and
preference transport. The seven recommended packages and existing feature hooks
are retained. The feature hooks still use the legacy API82 compatibility backend
permitted by target API101; this is not an API102-native port.

## Settings and lifecycle

- `META-INF/xposed/java_init.list` exposes `ModernXposedInit`. It dispatches
  `onPackageReady` into the existing hooks with the actual package class loader,
  application info and process name, including secondary packages in a process.
- `staticScope=true` declares the fixed seven-package scope. All supported
  dispatch branches are listed in `scope.list`; applying QOL to arbitrary other
  applications does not add functionality. API101 does not require every module
  to use static scope: modules with arbitrary app/IME targets need an extensible
  scope instead.
- The app uses its original `prefs` file with `MODE_PRIVATE`. The official
  `XposedService` connection replaces the world-readable-file activation test.
- Settings remain editable while disconnected. A connected service receives a
  complete typed snapshot through Remote Preferences, including deletions.
  Successful snapshots are deduplicated; a new connection always republishes.
  Failed writes remain pending and receive bounded retries. Tapping the status
  or reopening settings also retries.
- The remote `__miuiqol_api101_ready` marker is written in the same commit as the
  snapshot. Target processes skip initialization if no completed publication is
  present. Open module settings after enabling the module, wait for the sent
  status, then restart the corresponding target apps.
- Existing local settings stay in the same private file. Old settings stored in
  the framework's legacy NSP directory are **not automatically imported**. This
  version does not scan root-owned directories, change file permissions, or
  delete old files. Such settings must be configured again in this version.

Most options install hooks when a target process starts. Restart the appropriate
app after changing options, as required by the original module. A service
connection confirms only the configuration channel, not target-app injection or
that a feature works on a particular MIUI/HyperOS version.

## Build and check

Use JDK21, Android SDK36 and the repository's Gradle wrapper. The API101 service
AAR requires compileSdk36. The build uses AGP8.13.0, Kotlin2.2.21 and Gradle9.0.0;
the app's original minSdk/targetSdk behavior remains unchanged.

```sh
bash gradlew :app:testDebugUnitTest :app:assembleDebug :app:assembleRelease
python3 tools/verify_apk.py app/build/outputs/apk/debug/app-debug.apk --aapt2 "$ANDROID_HOME/build-tools/35.0.0/aapt2"
python3 tools/verify_apk.py app/build/outputs/apk/release/app-release-unsigned.apk --aapt2 "$ANDROID_HOME/build-tools/35.0.0/aapt2"
```

The APK verifier checks the actual DEX class definitions after optimization,
modern descriptor, scopes and merged manifest/provider. Framework API classes
must not be bundled into the APK. JVM tests cover publication, failures,
reconnection, deletion and the unpublished-settings gate. They do not exercise
Android Binder or the actual target applications.

The debug build uses `io.github.chsbuffer.miuihelper.debug` and a debug signature,
allowing a separate test installation. The optimized Gradle release output remains
unsigned. The APK distributed through this fork's GitHub Releases is re-signed
locally with a stable, fork-specific private key. A differently signed APK cannot
replace the upstream installation. No private signing key or password is included
in this repository or in the public release assets.

## Fork updates

Download releases from [Bigzhangbig/MIUIQOL Releases](https://github.com/Bigzhangbig/MIUIQOL/releases/latest).
The settings screen provides a manual **Check for updates** action that opens this
page and a separate [fork source](https://github.com/Bigzhangbig/MIUIQOL/tree/fix/lsposed-api101)
link. These actions do not detect, download or install updates automatically. The
original author and Telegram links remain available.

## Device acceptance

On a supported MIUI/HyperOS device with an API101-capable framework:

1. Enable this build and its seven recommended target packages in the manager.
   If the upstream module is also installed, disable it during this test so the
   two copies do not install the same hooks.
2. Open settings and confirm that the configuration has been sent. Toggle a
   default-on feature off, restart its target app, and confirm it is disabled.
3. Toggle it back on, restart again, and confirm its original behavior returns.
4. Reopen settings after a service/process restart and confirm local values are
   kept and published again. A disconnected service must show a disconnected
   status while local edits remain available.

Device execution and target-feature compatibility must be recorded separately
from build/test success; no device acceptance is implied by this document.
